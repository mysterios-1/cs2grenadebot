GrenadeCS2 — это Telegram-бот, который помогает игрокам в CS2 быстро находить и изучать раскидки гранат (смоки, флешки, хешки, молики) прямо во время игры.

Для пользователей
🗺️ 6 карт: Mirage, Dust II, Inferno, Nuke, Anubis, Ancient

💣 6 типов гранат: смоки, флешки, хешки, молики, инста-смоки, one-way

🔍 Круглый зум прицела — видно даже с телефона

⭐ Избранное — сохраняй любимые раскидки

📦 Комбо-связки — несколько гранат с одной позиции

💳 Оплата рублями через Platega (СБП / карта)

💫 Оплата Telegram Stars

Технологии, которые я выбрал

Когда я начинал делать бота, мне хотелось получить что-то лёгкое, полностью асинхронное и без лишних зависимостей. В итоге я остановился на таком наборе:

Python 3.13 — взял самую свежую версию языка
aiogram 3.22 — фреймворк для Telegram-бота
FastAPI + Uvicorn — чтобы принимать вебхуки от Platega
SQLite через aiosqlite — лёгкая асинхронная БД, не пришлось поднимать отдельный сервер
Pillow — для обработки изображений (зумлю прицелы на фото раскидок)
aiogram-sentinel — защита от троттлинга, чтобы бота не зафлудили
Platega API — приём платежей через СБП и карты
Telegram Stars — альтернативный способ оплаты прямо внутри Telegram

Как я разбил проект

Я специально не стал пихать всё в один файл, а разнёс код по модулям, чтобы потом самому было проще ориентироваться:

grenadecs2-bot/
bot.py — точка входа и основные хендлеры
admin.py — админ-панель с FSM для добавления раскидок
database.py — работа с SQLite (пользователи, раскидки, платежи)
keyboards.py — все инлайн-клавиатуры
callback_server.py — FastAPI для вебхуков Platega
platega.py — клиент Platega API
emojis_config.py — ID кастомных эмодзи
emojis_utils.py — утилиты для эмодзи
requirements.txt — зависимости
amvera.yml — конфиг для деплоя на Amvera
.env — переменные окружения (не попадает в Git)
data/smoke_bot.db — база данных (на сервере в /data/)

Как я запускаю бота локально
Вот последовательность, по которой я сам всё поднимаю.
Сначала клонирую репозиторий:
git clone https://github.com/твой_username/grenadecs2-bot.git
cd grenadecs2-bot
Потом создаю виртуальное окружение:
python -m venv venv
Дальше активирую его — на Windows через venv\Scripts\activate, а на Linux и Mac через source venv/bin/activate.
И ставлю зависимости:
pip install -r requirements.txt
Что я прописываю в .env
Создаю в корне проекта файл .env и кладу туда три обязательные переменные:

BOT_TOKEN=токен_от_BotFather
PLATEGA_MERCHANT_ID=merchant_id_из_ЛК_Platega
PLATEGA_SECRET=секретный_ключ_из_ЛК_Platega
PROXY_URL= (опционально, если использую прокси)

.env я никогда не коммичу в Git — все ключи живут только локально и на сервере.

Запуск
Тут всё максимально просто:
python bot.py
После этого бот начинает слушать Telegram API через aiogram, а параллельно поднимается HTTP-сервер на порту 8080 (FastAPI), который принимает вебхуки от Platega.
Как я деплою на Amvera
Для деплоя я подготовил amvera.yml с такими параметрами:

environment: python
toolchain:
pip: 3.13
requirementsPath: requirements.txt
scriptName: bot.py
persistenceMount: /data
containerPort: 8080

Порядок моих действий такой. В настройках Amvera добавляю переменные окружения BOT_TOKEN, PLATEGA_MERCHANT_ID, PLATEGA_SECRET со стадией «Запуск». Заливаю код командой git push amvera master. В разделе «Доменные имена» добавляю бесплатный домен Амвера — получаю что-то вроде https://твой-проект.твой-ник.amvera.io. Этот URL вставляю в личный кабинет Platega в поле Callback URL, добавив в конце /platega/callback.

Как у меня работает оплата
Логика такая:

Пользователь жмёт «Продлить доступ» в боте
Бот через create_platega_link создаёт ссылку на оплату через Platega API
Пользователь переходит и платит через СБП или карту
Platega шлёт POST на callback_server.py по адресу /platega/callback
Мой сервер проверяет заголовки X-MerchantId и X-Secret
Если статус CONFIRMED — начисляю дни через add_days, пишу платёж в БД для статистики и отправляю пользователю сообщение об успешной оплате

Реферальная система

Я добавил рефералку, чтобы пользователи сами приводили новых людей:
При переходе по ссылке /start ref_USER_ID новый пользователь получает +7 дней доступа
Реферер получает +7 дней и уведомление
Команда /refstat показывает, сколько всего людей перешло по ссылке и сколько из них купило подписку

Кастомные эмодзи
В боте я использую Telegram Premium Emoji через тег tg-emoji с emoji-id.

Все ID храню в emojis_config.py
Fallback (обычные эмодзи) — в emojis_utils.py

Использую это так:
from emojis_utils import emoji
text = f"{emoji('smoke')} Смоки"

База данных

Путь к БД: на сервере — /data/smoke_bot.db, локально — ./data/smoke_bot.db.

Что я предусмотрел по безопасности

Все ключи храню в .env, в Git они не попадают
Callback от Platega проверяю по заголовкам X-MerchantId и X-Secret
Анти-троттлинг работает через aiogram-sentinel
Перед каждым действием проверяю доступ через check_access()
Защита от повторных кликов — игнорирую ошибку message is not modified

Проблемы:

Проблема с зумом: сначала делал вручную через Paint, это был ад. Потом написал скрипт на Pillow, который берёт центральную область фото и увеличивает её в 2 раза с круглой маской. Это ускорило процесс в десятки раз. Позже добавил команду /focus, которая прогоняет все фото прицелов в базе и обновляет их одной командой.

Следующая проблема — скорость. Когда пользователь в катке нажимает кнопку, каждая секунда важна. Переписал все запросы к БД через asyncio.gather, чтобы они выполнялись параллельно. Убрал лишние вызовы check_access там, где они дублировались. В итоге бот стал реагировать мгновенно.

Проблема с базой данных на хостинге. Amvera затирает папку проекта при пересборке, поэтому база в /app/data/ теряется. Решение: хранить базу в /data/, которое монтируется как постоянное хранилище. Это описано в amvera.yml через persistenceMount. После этого раскидки перестали пропадать при деплое.

Проблема с оплатой. ЮKassa отказала, Robokassa отказала (позвонили и сказали «не обращайтесь»), Ckassa требовала бумажные документы. В итоге подключил Platega — да, комиссия выше, да, юридически «серая» схема, но она работает здесь и сейчас. Позже добавил Telegram Stars как альтернативу, чтобы не зависеть от одного провайдера.

Проблема с Callback URL. Platega отправляет POST-запрос на сервер, когда платёж проходит. Без этого бот не знает, что начислять дни. Пришлось поднять FastAPI прямо в том же контейнере, где работает бот. Теперь бот и вебхук-сервер живут вместе, на одном порту 8080.

Проблема с защитой от флуда. Когда пользователь быстро тыкает кнопки, Telegram начинает банить бота за слишком частые запросы. Подключил aiogram-sentinel, который ставит лимит 5 запросов за 10 секунд на пользователя. Кнопки перестали виснуть.

Проблема с избранным. Сначала сделал просто список, но пользователи просили сортировку по картам. Переделал: теперь избранное открывается через меню карт, а раскидки показываются только те, что сохранены на конкретной карте. Это добавило удобства.

Проблема с комбо-связками. Когда несколько гранат кидаются с одной позиции, их надо показывать как одну связку, а не как отдельные раскидки. Добавил поле combo_id в базу, и теперь при просмотре можно переключаться между прицелами одной связки.

Проблема с реферальной системой. Сначала бонус начислялся даже тем, кто уже был в боте. Переписал add_user так, чтобы проверка была строго при первом входе, и чтобы реферер получал уведомление с именем нового пользователя и новой датой подписки.

Проблема с кастомными эмодзи. Telegram Premium Emoji работают только через tg-emoji с emoji-id. Если ID неправильный или эмодзи нет — показывается fallback. Сделал два словаря: CUSTOM_EMOJIS с ID и EMOJI_FALLBACK с обычными эмодзи. Если ID нет — используется fallback, бот не падает.

Проблема с редактированием сообщений. Telegram не даёт редактировать фото через edit_caption, если в сообщении уже фото. Приходится использовать edit_media или удалять и отправлять заново. Сделал универсальный подход: где возможно редактирование, где нет — удаление и отправка.

Проблема с фильтрами по зонам. Изначально кнопки «Плент А», «Плент Б», «Мид», «Ситуация» не работали, потому что для ситуационных раскидок сторона не учитывается, а в callback_data она передавалась. Переписал логику парсинга callback_data, чтобы для ситуационных зон сторона игнорировалась.
